# VRM 対応の調査

調査日：2026-11-13。結論と作業量の見積もりを先に書き、根拠をその後に置きます。実装はまだ行っていません。

## 結論

- **対応は可能です。** VRM を読み込むときに、ランタイムが今使っている PMX と同じデータ構造（`mmd::PmxModel`）に変換する方式が最も手戻りが少ないと考えます。描画、自前のスキニング、VMD、モーションの自動生成、着席、当たり判定、SAORI 連携をそのまま使えます。
- 変換で失われるものが 2 つあります。揺れもの（SpringBone）と、MToon の見た目の細部です。揺れものは、このランタイムがスキニングの直前にボーンを持っている構造なので、その位置に VRM の参照アルゴリズム（ボーンごとの単純な Verlet 法）を足すのが自然です。Bullet の剛体に置き換える必要はありません。
- 変換した PMX をファイルに書き出す方式（Blender のアドオンなどで変換してから読み込む方式）は勧めません。VRM のライセンス情報には「改変」の許可欄があり、改変を禁止したモデルが多いためです。読み込み時にメモリ上で変換し、ファイルは作らないようにします。

## 変換の内容

| VRM | このランタイムでの扱い |
|---|---|
| glTF 2.0 バイナリ（.vrm は .glb と同じ） | cgltf で読む。テクスチャはファイル内の PNG／JPEG なので、ファイル名ではなくメモリから読み込む経路を `TextureCache` に足す（今はファイルから読む `CreateDecoderFromFilename` だけ） |
| 座標系：右手系・Y 上・メートル。0.x は −Z 向き、1.0 は +Z 向き | MMD は左手系・−Z 向きで、1 単位はおよそ 8cm。1.0 は Z を反転し、0.x は X を反転して、どちらも 12.5 倍する |
| 基本姿勢：T ポーズ。1.0 はボーンが初期姿勢で回転を持つ | PMX のボーンは回転を持たないので、各ボーンの初期姿勢でのワールド位置だけを使う。頂点は inverseBindMatrices から求めた基本姿勢の座標に直す |
| 人型ボーン（hips、spine、chest、upperLeg、lowerLeg、foot、toes、upperArm、lowerArm、hand、指など） | `センター`／`下半身`／`上半身`／`上半身2`／`首`／`頭`、`左足`／`左ひざ`／`左足首`／`左つま先`、`左腕`／`左ひじ`／`左手首` などに名前を付け替える。それ以外のノードは元の名前のまま。着席・当たり判定・生成モーションがボーン名で動く |
| 1 頂点 4 ボーンまでの重み（`JOINTS_0`／`WEIGHTS_0`） | BDEF1／BDEF2／BDEF4。`JOINTS_1` がある場合は重みの大きい 4 本に絞って正規化する |
| 表情（1.0：happy、angry、sad、relaxed、surprised、aa、ih、ou、ee、oh、blink、blinkLeft、blinkRight、lookUp など。0.x：Joy、A、Blink など） | メッシュごとのモーフターゲットを頂点モーフにし、表情をグループモーフにまとめる。名前は `笑い`、`怒り`、`困る`、`なごみ`、`びっくり`、`あ`／`い`／`う`／`え`／`お`、`まばたき`、`ウィンク`、`ウィンク右` に合わせ、辞書の `Set3DMorph` がそのまま使えるようにする。マテリアルの色を変える表情は材質モーフに変換する |
| SpringBone（1.0：springs／joints／colliders、0.x：secondaryAnimation） | 段階 2 で、自前の Verlet 計算として実装する。剛体はないので Bullet の物理は使わない |
| MToon | 段階 3 までは、基本色テクスチャ、影色、輪郭線（PMX のエッジ）だけを近似する |
| ライセンス情報（meta） | 読み込み時にログとステータスへ出す。ランタイムは変換結果をファイルに書かない |

## 生成モーションとの相性

- VRM は T ポーズ、一般的な MMD モデルは腕を 30〜40° 下げた姿勢を基本姿勢にしています。既存の VMD を VRM にそのまま当てると、腕が上がって見えます。
- `uka3d_motiongen` は、モデルの基本姿勢から腕の角度、脚の長さ、足の大きさを測ってモーションを作ります。そのため、ボーン名を対応付ければ、待機・歩行・着席・つまみは VRM でも同じ方法で作れます。挨拶とうなずき（角度を直接書いた合成モーション）は、T ポーズでは腕の角度がずれます。

## 実物での確認（Seed-san）

VRM の公式リポジトリにあるサンプル Seed-san（VRM Public License 1.0、VirtualCast, Inc.）を手元に取得して、中身を読みました。リポジトリや配布物には含めていません。

| 項目 | 内容 |
|---|---|
| 形式 | VRM 1.0（`VRMC_vrm`、`VRMC_springBone`、`VRMC_materials_mtoon`、`VRMC_node_constraint` などを使用） |
| メッシュ | 5 メッシュ、21 プリミティブ、34,059 頂点、モーフターゲット 129、スキン 5 |
| 重み | 1 頂点 4 ボーンまで（`JOINTS_1` なし） |
| マテリアル | 17（MToon 10、Unlit 10、半透明あり）。テクスチャ 15 枚はすべてファイル内の PNG |
| 人型ボーン | 51 本。すべてのボーンが初期姿勢で回転を持つ。スケールを持つノードが 131 個 |
| 姿勢と向き | 腕は水平から 0.5° 下（T ポーズ）。つま先は +Z 側（+Z 向き）。腰の高さ 0.80m、頭 1.33m |
| 表情 | 1.0 のプリセット 18 種すべて |
| 揺れもの | 9 本、関節 28、コライダー 8 |
| ノードコンストレイント | 23 |
| ライセンス情報 | avatarPermission `everyone`、modification `allowModificationRedistribution`、creditNotation `required` |

## 注意点

- VRoid Hub などで配布されているモデルは、作者ごとに利用条件が違います（avatarPermission、commercialUsage、modification、allowRedistribution など）。ゴーストに同梱して配布できるかどうかはモデルごとに確認が必要です。ランタイムは条件をログに出しますが、判断はゴーストの作者が行います。
- VRM 1.0 の +Z 向きは、仕様書の該当ページでは確認できていません。Seed-san の実データ（つま先が +Z 側）から判断しました。0.x の −Z 向きと T ポーズは仕様書に明記されています。
- VRM 0.x の実データはまだ確認していません。
